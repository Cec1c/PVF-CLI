# 实施计划

阶段0、阶段1及阶段2的既有条目raw／token编辑已实现。新增路径和通用文本编译未接入CLI；阶段3的磁盘读取／有界缓存仍待实施。以下保留各阶段验收要求，当前接口见 [CLI.md](CLI.md) 与 [PATCH.md](PATCH.md)。

## 阶段 0：独立核心与验证基线

- 从冻结快照提取必要代码，保留来源信息；选定独立模块路径，调整内部 import。
- 只引入实际必要依赖。`go.mod` 里的游戏服务器、数据库和网络框架依赖不迁入。
- 迁移合成 NKPI 及字符串修改测试；梳理 protected NKPI 的合成覆盖缺口。
- 整理 archive、entry、token 层的类型、错误和接口，先保持已验证的格式行为。
- 使用独立缓存，跑最小包测试与构建。记录依赖、工具链、产物大小。

完成标准：无需原服务端目录、PUT 或真实 PVF，即可构建核心并通过合成测试。

## 阶段 1：只读 CLI

| 建议子命令 | 目标行为 |
| --- | --- |
| `info` | 报告格式、文件规模、条目数、支持情况；提供稳定 JSON |
| `list` | 按路径/前缀过滤；支持明确的数量限制，报告是否截断 |
| `read` | 显式选择 text/raw/token 表示；不支持的表示明确失败 |
| `search` | 区分路径搜索和正文搜索；限定前缀、数量、并发及取消行为 |
| `export` | 导出选中条目；保留目录结构或明确映射；防止越出输出目录 |

统一参数中显式指定输入 PVF。标准输出只放结果或机器可读 JSON，进度和诊断走 stderr。raw 输出不混入日志；二进制重定向在 Windows 上需验证，必要时提供直接文件输出参数。

定义并记录成功、用法错误、归档/输入错误、未找到结果等退出约定。批量操作不得静默跳过失败条目；列出失败数和失败路径。

完成标准：覆盖 [验收标准](VALIDATION.md) 的只读项，能在指定真实样本上核对文本与 raw，记录耗时和内存。超大输入的行为应明确，不隐藏默认大小上限。

## 阶段 2：受控修改与验证

- 优先接入已有字符串引用替换、现有条目 raw 替换，再评估 token 编辑与新增脚本。
- 修改计划明确列出目标路径、原内容/摘要预期、修改类型和输入 SHA256；支持预览。
- 输出必须独立于输入，包括大小写、相对路径、硬链接等同一文件别名检查。
- 先写临时输出，重新打开并验证，成功后交付目标文件；失败清理本次临时产物并保持输入不变。
- 比较目标预期、条目清单、共享池引用及未修改条目的 raw 摘要。若只抽样，报告抽样范围，不能宣称全档保持。
- 共享字符串池修改与单脚本引用修改分开，说明影响范围。

完成标准：原始样本摘要保持不变，目标修改符合预期，其余条目符合所选择的验证级别，结果报告能追溯输入、输出和校验。

## 阶段 3：保真与性能

- 建立可无损表示的 token 格式，先验证 round-trip 再增加可读文本编译能力。
- 优先支持当前已有证据的格式；新变体单独登记并建立样本测试。
- 评估磁盘读取、共享目录索引和有界缓存，比较冷/暖运行与峰值内存。
- 验证目标平台，整理帮助、使用示例与发行流程。完整 PUT 功能替代和 GUI 不属于默认范围。

## 建议目录

实际结构可随实现调整，避免在没有代码时先造大量空包。

```text
cmd/pvf/          CLI 入口
internal/pvf/     归档、编码、token 和重打包
internal/cli/     参数、结果输出与命令组合（有需要再拆）
internal/cli/testdata/  可公开的合成最小样本
docs/            格式、用法、兼容性与验收记录
runtime/         ignored 的真实样本输出及报告
```

原生客户端验收只在明确安排时进行。CLI 的库回读和自动化测试通过，不自动触发游戏启动或线上替换。
